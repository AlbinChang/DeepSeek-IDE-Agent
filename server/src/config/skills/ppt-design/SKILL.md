# PPT / 幻灯片设计规范

## 1. 交付形态

- 默认交付 HTML 文件：外层 HTML 只做容器与翻页控制，全部视觉内容用 SVG 绘制。
- 每页是一个独立 `<svg>`，`viewBox="0 0 960 540"`，对应 960pt × 540pt 标准宽屏画布（16:9，1pt = 1/72in）。
- 页面内的坐标、尺寸、边距、字号一律使用 pt；禁止混用 px/in/cm/rem，禁止 1920×1080 / 1280×720 像素画布，禁止 4:3，禁止页间尺寸不一致。
- HTML 容器：`width:1280px`（= 960pt 的 CSS 等价像素），`max-width:100vw`，`aspect-ratio:16/9`。

## 2. 页面规划（生成前必须完成）

没有页面规划时，严禁一次性生成全部页面。先用 `append_todo` 建立页级任务清单，至少覆盖：

1. 整体主题、受众与叙事顺序；
2. 总页数与每页标题 / 核心信息 / 布局类型；
3. 封面方案；
4. 栅格、边距、字号档位与元素尺寸基线；
5. 每页的 SVG/图表/表格承载方式；
6. 纵向高度预算（顶部 / 中部 / 底部各占多少、各自承载什么）；
7. 左右半屏视觉重量与留白比例预算；
8. 文字颜色与容器背景色的对比方案；
9. 潜在重叠 / 溢出 / 低对比风险。

每页 TODO 必须写明：顶部承载什么、中部承载什么、底部承载什么、左侧承载什么、右侧承载什么、主要文字色与容器背景色是否高对比、视觉重心是否上下/左右均衡。若某页采用全宽 / 居中 / 上下布局，也必须说明不存在左满右空、右满左空、上满下空、文字低对比、下方无意义留白等风险。

## 3. 结构分离（HTML vs SVG）

- SVG 是唯一绘制引擎：所有文字、图形、卡片、表格、图表、流程、时间轴、装饰元素都由 `<svg>` 内的 `rect` / `text` / `path` / `line` / `image` 等元素绘制。
- 禁止用 HTML `<div>` 卡片、`<table>`、`<p>` / `<span>` 文本块、CSS 盒子布局承载页面内容。
- HTML 保持极简：外层包裹器 + 各页 `<svg>` + 翻页工具栏，不掺杂内容性元素。
- 复杂图形（架构图、流程图、关系网络、时间轴）必须用矢量元素组织，不得贴位图充数。
- 生成时逐页自检：该页所有可见内容是否都在 SVG 内？HTML 是否只剩容器与翻页逻辑？

## 4. 浏览器缩放必须有效（响应式缩放）

- 原理：CSS px 是缩放敏感单位，vw/vh 是视口百分比单位（缩放后视觉占比不变），因此幻灯片容器严禁用 `100vw` / `100vh`。
- 换算基准：960pt × (96/72) = 1280px，540pt × (96/72) = 720px。1280px 是 960pt 画布的精确 CSS 等价像素，不是随手取的数；打印时浏览器会把 1280 CSS px 映射回 960pt。
- HTML 必须包含 `<meta name="viewport" content="width=device-width, initial-scale=1.0">`。
- `body`：`margin:0; overflow:auto; display:flex; justify-content:center; align-items:center; min-height:100vh;`（overflow 用 auto，允许放大后滚动）。
- `.slides-container`：`width:1280px; max-width:100vw; aspect-ratio:16/9; position:relative;`。
- 每页 SVG：`width="100%" height="100%"`，保留 `viewBox="0 0 960 540"`；`.slide`：`position:absolute; top:0; left:0; width:100%; height:100%;`。
- 缩放验收：100% 时约占视口 2/3～全宽；50% 时明显缩小到约 1/3～1/2 视口，可看到完整页面；200% 时填满视口并可滚动平移查看细节。
- 严禁反模式：`width:100vw;height:100vh`（缩放无效）、`overflow:hidden`（放大后裁剪）、`width:960px`（960px ≠ 960pt）、`width:1920px`（脱离换算基准）。

## 5. 视觉风格

- **明亮清晰**：默认浅色或近白背景、清爽留白、深色高对比正文、少量明快强调色。禁止黑/深灰/深蓝/暗紫/暗色渐变或夜间科技风做主视觉；除非用户明确要求暗色主题。
- **封面要有冲击力**：第一页是全套材料的视觉锚点，优先全画幅构图、强视觉中心、清晰主标题、克制的副标题/元信息，配主题相关的抽象图形、数据地形、架构意象或场景化背景。禁止把封面做成普通正文页、白底标题页、卡片堆砌页或大段说明页。
- **文字与背景对比度**：每个文字承载容器（卡片、流程节点、表格单元、标签、标题条、注释框、封面覆盖层、SVG text 背板）都必须检查前景色与直接背景色的对比——正文/小字 ≥ 4.5:1，大标题 ≥ 3:1。禁止浅字配浅底、深字配深底、同色系相撞、透明/渐变/图片背景上直接放无背板文字。背景复杂时加半透明遮罩、纯色底板、描边/阴影或改用高对比文字色。
- **图标与标题同一行**：图标与对应标题必须同基线同行呈现。空间不足时缩小图标/字号或重排容器，禁止拆成上下两行。
- **禁止文字平铺**：所有文本单元都必须有明确视觉边界——卡片（背景色 + 圆角 + 细边框/微阴影的 `<rect>`）、流程节点（圆角矩形/胶囊 + 连线）、标签徽章、表格单元格、时间轴节点、矩阵象限、指标卡等。禁止裸 `<text>` 直接铺在画布上；禁止整页左侧一列无背景 bullet；禁止大段说明文字直接写在空白背景；禁止关键数字无衬底；禁止段落文字无分区无边界。
- 正确做法：语义相关的一组内容封装为一个带背景色、圆角和细边框的 SVG 卡片（`<rect>` + `<text>` 组合）；列表项用横向/网格卡片组而非纵向裸 bullet；关键数字放进醒目的指标卡（大号数字 + 小标签 + 背景色块）；不同层级用容器底色深浅、边框粗细、阴影层次区分。

## 6. 空间完整性（零重叠 / 零溢出 / 纵向适配）

- **零重叠**：任意元素之间不得有可见重叠。
- **零溢出**：所有元素完整位于画布可视范围内，文本不得裁切、遮挡或越界。
- **纵向适配**：基于 540pt 高度做预算，任何元素满足 `y + height < 540pt - 安全区`；超高时改为分页或多列布局。
- **容器内文字不溢出**：文本在卡片/表格单元/流程节点/标签框内完整可见且可读；空间不足时换行、扩容或拆分成多个容器。
- 禁止用滚动条、`overflow:hidden` 或裁切来掩盖溢出。

## 7. 布局平衡

- **上下分区**：画布拆为顶部标题/导语区 + 中部核心图形/论证区 + 底部总结/指标/锚点区。禁止上满下空（下方 30% 以上空白且无信息承载）。
- **左右平衡**：按中线检查左右半屏的信息承载、图形面积、模块数量和视觉重量；一侧视觉重量低于另一侧 60%，或出现连续大空白时，必须补充结构化 SVG / 关键数字 / 摘要卡 / 流程图，或改为全宽 / 上下分区 / 网格布局。
- 留白必须是有意的呼吸空间，不能是内容停止后的剩余空地。

## 8. 翻页工具栏

- 锚定在右下侧安全区悬浮覆盖，不占用正文版心，禁止放在中下部或遮挡主要内容。
- 用户停止交互 2 秒后自动隐藏；鼠标移动/点击/翻页时短暂显示并重新计时，禁止常驻遮挡内容。

## 9. 逐页生成与逐页检查

按页推进：每完成一页就更新对应 TODO 并执行逐页检查，未通过先修该页，禁止带问题进入下一页或交付。

逐页检查清单：

1. 画布 960pt × 540pt、单位全程 pt、无 1920/1280 像素画布混入；
2. 无重叠、无溢出、无裁切；
3. 纵向高度预算合理，上中下三区都有承载；
4. 容器内文字完整可读；
5. 文字色与容器背景色对比达标（正文 ≥ 4.5:1，大标题 ≥ 3:1）；
6. 留白有意、上下左右视觉平衡，无上满下空/左满右空/右满左空；
7. 视觉风格明亮清晰，封面有冲击力；
8. SVG 可正常渲染，连线端点精确对齐；
9. 字号可读（正文不小于 12pt，注释不小于 9pt）；
10. HTML 中无内容性元素混入。

## 10. 全面检查 / 全面修复模式

当用户要求「全面检查、全面修复、整体优化、排版修复、问题排查、质量验收」时，禁止笼统扫一眼就给总体结论。

1. 先识别全部页码，用 `append_todo` 建逐页检查修复清单。每页 TODO 至少包含：检查对象、检查维度、左右半屏承载情况、文字色/容器背景色对比情况、发现的问题、修复动作、复查结论。
2. 按页顺序逐页打开、逐页检查、逐页修复、逐页复验，每页闭环后再进入下一页。
3. 最终输出问题清单与修复结果对照表（页码 / 问题 / 修复动作 / 复查结论），不得遗漏页码。

## 11. 内容质量

- 禁止同义重复、段落重复、页面重复、空话套话、前后矛盾。
- 关键结论、数据口径、时间、主体、范围必须全篇一致。
- 依据不足时继续找材料或标注「待确认」，禁止臆断、虚构数据/案例/引用，禁止用重复内容凑页数。
