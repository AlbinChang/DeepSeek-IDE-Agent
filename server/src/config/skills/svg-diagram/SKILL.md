# SVG / 图表设计规范

## 1. 输出格式选择

1. **SVG（矢量，最高优先级）**：纯文本 XML，可直接编辑、可 git diff、无限缩放不失真、体积小、可用 CSS 控制样式。适用于图表、流程图、架构图、图标、UI 原型、数据可视化。
2. **PNG（栅格）**：仅在浏览器截图、照片级图像、SVG 无法表达的复杂渐变/阴影、需要跨平台像素级一致时使用。
3. **禁止** JPG/GIF/BMP/TIFF（用户明确指定除外）。

## 2. Markdown 文档中的图表策略

1. 简单图表（流程示意、关系图、架构概览、组织图、树形结构）→ 优先用 Unicode/ASCII 文本图：`┌┬┐├┼┤└┴┘│─`、箭头 `→↑↓←↗↘`、方块 `▀▄█`。文本图可直接嵌入 .md，无外部依赖、易维护、易修改。
2. 时序图 → 使用 Mermaid（对 sequenceDiagram 支持最成熟：参与者、消息、生命线、激活框、备注语义完整）。
3. 其他复杂图表（类图、ER 图、状态图、Gantt、pie）→ 可用 Mermaid，但先确认该图表类型的 Mermaid 支持成熟度。
4. 禁止：为画简单图表引入 matplotlib/seaborn/numpy 等重量级依赖；在 .md 中 base64 内嵌位图。

## 3. 图标选择

1. UTF-8 字符 / Emoji（最高优先级）：文件 📁📂📄📝🗑️💾、技术 ♻️⚡🔧🔗🌐📡、状态 ✅❌⚠️⏳ℹ️🔴🟡🟢、导航 🏠⬆️⬇️⬅️➡️🔙、工具 🔍⚙️🔑💡📌📎、图表 📊📈📉、代码 💻🐛🚀🧪📦🎯、文字 ✏️📋💬🗨️📢🔔、符号 ◆◇○●□■△▲☆★→←↑↓↗↘∙•…‰€£¥©®™±×÷≈≠≤≥。优势：零体积、跨平台、可搜索。
2. 内联 `<svg>...</svg>`：UTF-8 字符不够用时（复杂图标、品牌 logo、自定义形状）。
3. 禁止：点阵字符画（用 `*#@` 拼图）、base64 内嵌位图图标、外部图标字体（如 Font Awesome）。用户明确指定图标库时按用户要求执行。

## 4. SVG 绘制规范

- 画布用 `viewBox` 定义坐标系；为每个图设定明确的宽高比，避免内容被拉伸。
- 结构分层：背景层 → 容器/卡片层 → 连线层 → 文本层 → 装饰层；层次用 `<g>` 分组并加 `id`/注释。
- 文本必须可读：`font-size` 不小于 10；文字与其背板颜色对比度 ≥ 4.5:1；长文本用 `tspan` 换行或 `foreignObject` 前先确认渲染兼容性。
- 连线端点必须精确对齐节点边缘，禁止悬空或穿模；折线用 `<polyline>` 并保证拐点坐标可读。
- 箭头用 `<marker>` 定义，避免每根线手绘三角形导致端点错位。
- 元素零重叠、零溢出：先算布局坐标（栅格法），再写元素，禁止凭感觉堆叠。
- 不使用 `filter` 实现必须的视觉信息承载（导出兼容性差）；阴影仅作点缀。
- 图片引用用相对路径或内联矢量，禁止 base64 大图。
- 自检：打开渲染结果（浏览器 `file://` 预览）确认无裁切、无错位、文字未溢出容器。

## 5. 图表选型对照

| 需求 | 推荐形式 |
| --- | --- |
| 业务流程 / 决策分支 | Mermaid flowchart 或 ASCII 流程图 |
| 前后端交互 / API 调用链 | Mermaid sequenceDiagram |
| 数据模型 / 类型关系 | Mermaid classDiagram |
| 数据库表关系 | Mermaid erDiagram |
| 状态机 / 生命周期 | Mermaid stateDiagram |
| 系统组件拓扑 | SVG 架构图（分组 + 连线 + 图例） |
| 指标对比 / 趋势 | 表格、ASCII 柱状图或 SVG 图表 |

## 6. 视觉一致性

- 配色克制：主色 ≤ 3 种，背景统一，强调色只用于重点。
- 同一文档/同一交付物内图表的字号档位、线宽、圆角、配色保持一致。
- 留白 ≥ 15%，避免元素贴边。
